## 0. Root cause (confirmed)

`AlpacaBroker::wait_for_fill` (`crates/data_feed/src/broker.rs:276-283`) polls with `apca::api::v2::order::Get`. apca 0.30.0 builds that path as `format!("/v2/orders/{}", id.as_simple())`, which is the UUID **without hyphens** (`apca-0.30.0/src/api/v2/order.rs:751`).

Read-only checks against the paper API today, using the same order ID:
- **hyphenated UUID:** HTTP 200.
- **un-hyphenated UUID:** HTTP 422 `{"code":40010001,"message":"invalid order_id"}`.

The 10-12 NVDA round trip went through this same poll and worked. So **Alpaca stopped accepting the simple-form ID between 10-12 and 10-15**. Nothing changed on our side: there has been no `Cargo.lock` or `broker.rs` change since `0900760`.

The failure chain:
1. The order is created and fills.
2. The poll returns 422, which the engine reads as a `ConnectionError`.
3. `book.rs` logs "broker order failed, undoing position" and calls `undo_open`.
4. The window re-fires on the next qualifying bar (AMZN fired 4 times).

Consequences while this is unfixed:
- **No primary entry can succeed.** Every signal leaves an orphan.
- The cancel-on-timeout path (`order::Delete`, same `as_simple` path) is very likely broken too.
- If `close_position` waits on the resulting order through the same poll, exits are affected as well. That has not been tested today because no entry survived.
- **Watchdog blind spot:** `scripts/watchdog.sh` reads `engine_state`, not the broker. At 15:15 ET it reported "primary: flat" while the account was short 48 AMZN.

**Needs the human, before 06:10 PT tomorrow:**
1. **Close AMZN −48 and NVDA −14** in the Alpaca paper dashboard at or after the open. The routine never trades.
2. Either patch the poll or set `BROKER_MODE=simulated` for Friday.
   - The patch: get and delete orders by the hyphenated ID through a raw request, the same pattern as the lenient `/v2/account` call in `account.rs`.
   - Otherwise Friday repeats today.
3. Optional: have the watchdog compare `engine_state` to `/v2/positions` once a run.

The pre-open check already treats the startup line `BROKER HOLDS A POSITION THE ENGINE DOES NOT KNOW ABOUT` as CRITICAL (`.claude/skills/preopen-check/SKILL.md:51`), so it will fire at 06:15 PT if these positions are still open.
